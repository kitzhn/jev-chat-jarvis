# 联系人画像、跨 App 身份与关系模型

此功能只保存用户主动维护的数据，不包含任何预置个人联系人，也不会从聊天内容自动推断好感度或对方真实心理。

## 核心模型：一个人，多个平台身份

联系人（Contact）代表一个现实中的人或群体。一个联系人可以绑定多条平台身份（PlatformIdentity）：

```
Contact
├── name: 用户给这个现实联系人的显示名称
├── identities
│   ├── QQ + 会话标题
│   ├── 飞书 + 会话标题
│   └── X + 会话标题
├── relationship / relationshipStage
├── affection / trust / closeness
└── profile fields...
```

匹配顺序：

1. 优先使用 **App package + 会话标题** 精确匹配 PlatformIdentity。
2. 如果没有精确身份，再使用旧版本的 name / aliases 规则兼容已有数据。
3. 不因为“不同 App 里昵称看起来相似”自动合并联系人。

这样可以避免两个不同的人恰好同名时被错误串联。

## 从聊天界面关联现有联系人

悬浮球长按菜单提供：

- 把当前会话存为联系人
- 关联当前会话到已有联系人

第二项会打开联系人列表，并携带当前 App 和会话标题。用户点选现实中的同一个联系人后：

- 当前 App + 会话标题被写入该联系人的 identities；
- 以后该 App 的这个会话会命中同一 Contact；
- 不同 App 的聊天共用联系人画像、关系模型和历史上下文。

如果该精确平台身份已经属于另一个联系人，则认为之前创建了重复联系人。因为这次合并是用户显式选择触发的，系统会把重复联系人合并到用户选中的主联系人：

- 平台身份合并；
- 别名 / App / 画像标签合并；
- 聊天历史按时间合并并去重；
- 好感变化日志合并；
- 主联系人的关系分数优先保留；
- 主联系人非空画像字段优先，重复联系人中的其它文本追加保留。

## 联系人画像

每个联系人可维护：

- 名字与旧式全局别名
- 多个平台身份
- 关系类型
- 当前关系阶段
- 好感度（0–100）
- 信任度（0–100）
- 亲密度（0–100）
- 画像标签
- 性格 / 长期特征
- 沟通偏好
- 边界 / 忌讳
- 备注
- 本地聊天历史
- 好感变化日志

所有数据仍保存在 App 私有目录：

```
filesDir/kb/
├── contacts.json
├── notes.json
├── logs/<contactId>.json
└── relations/<contactId>.json
```

## 好感度量级

| 分数 | 阶段 |
| --- | --- |
| 0–19 | 冷淡 |
| 20–39 | 疏远 |
| 40–59 | 普通 |
| 60–79 | 亲近 |
| 80–94 | 信赖 |
| 95–100 | 特别亲密 |

默认值为 50。

联系人卡片包含：

- 首字头像占位
- 关系阶段徽章
- 好感进度条
- 信任 / 亲密数值
- 已绑定的平台身份
- 最近互动时间
- 最近两条好感变化
- ±5 快捷调整
- 完整好感变化记录

快捷调整时可以填写“为什么变化”。每条 RelationshipEvent 保存：

- 时间
- 变化值
- 变化前分数
- 变化后分数
- 原因
- 来源（快捷调整 / 画像编辑）

## AI 上下文

当聊天命中联系人时，关系模型会作为背景信息提供给判断 / 回复流程，包括：

- 关系类型与阶段
- 好感 / 信任 / 亲密
- 已关联平台身份
- 画像标签与特征
- 沟通偏好
- 边界与备注

上下文会明确标记这些资料是“用户手动维护的关系模型”，不能当作对方真实心理或客观事实。

## 兼容性

旧版本 `contacts.json` 没有新字段时：

- identities 默认为空
- 好感度默认 50
- 信任度默认 50
- 亲密度默认 50
- 其它新增字段默认为空
- 旧 name / aliases / apps 仍然可以用于兼容匹配

因此无需单独的数据迁移步骤。
